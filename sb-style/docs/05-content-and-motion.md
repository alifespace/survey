# 内容与动效

## 文案语气

目标语气是“懂工程的产品伙伴”：直接、具体、平静，不夸张，也不把简单事情说复杂。

### 原则

- 先说用户能完成什么，再说产品用了什么技术。
- 使用主动语态和现在时。
- 一个按钮只表达一个动作。
- 用事实、时间、规模和具体对象替代形容词。
- 技术术语在能减少歧义时使用，并在首次出现时解释。
- 中文界面默认使用句式大小写逻辑；英文 UI 使用 sentence case。

### 改写示例

| 避免 | 推荐 |
| --- | --- |
| 下一代革命性平台 | 在一个工作区管理数据、权限和部署 |
| 极致提升开发效率 | 用预置认证和 API 在一天内完成原型 |
| 点击这里 | 查看实时日志 |
| 操作失败 | 无法保存设置。检查网络后重试。 |
| 确定要继续吗？ | 删除后无法恢复。删除项目？ |

## 标题公式

推荐组合：

```text
动词 + 用户结果
从起步速度到增长规模的对照
具体能力 + 明确场景
```

示例仅用于结构参考：

- 今天完成接入，增长后无需重写
- 让每次部署都有迹可循
- 从第一条事件到千万级数据

## 技术内容

- 代码必须能运行或明确标注为伪代码。
- 省略内容使用注释说明，不能悄悄删除关键步骤。
- 复制按钮复制纯代码，不包含行号和提示符。
- 错误示例同时展示修复方式。
- 文档链接进入具体章节，不只链接到文档首页。

## 动效原则

动效服务于三件事：说明关系、确认操作、保持上下文。纯装饰动效保持稀少。

### 时长与曲线

| 场景 | 时长 | 建议曲线 |
| --- | --- | --- |
| Hover / 按压 | `100–160ms` | `ease-out` |
| 菜单 / Tooltip | `140–200ms` | `ease-out` |
| Tab / 内容切换 | `180–260ms` | `ease-in-out` |
| 大区块进入 | `320–480ms` | 柔和 `ease-out` |

### 使用规则

- 页面进入动效只移动 `8–16px`，不要大幅飞入。
- 列表错峰间隔不超过 `40ms`，总等待不超过 `300ms`。
- Hover 不使用明显缩放，避免像广告落地页。
- Tab 切换保持容器高度稳定，避免布局跳动。
- 数据流动效可循环，但必须低对比，并在标签页不可见时暂停。
- `prefers-reduced-motion: reduce` 下移除位移动画、视差和无限循环。

## 加载与空状态

- 预计少于 300ms 的操作不显示 Spinner，避免闪烁。
- Skeleton 应模拟真实内容结构，不能用大量无意义灰条。
- 空状态说明为什么为空，并给出一个最可能的下一步。
- 错误状态保留用户已经输入的内容。

## 国际化

- 为中文、英文长度差异预留 30% 空间。
- 不在 CSS 中把文本固定为单行，除非它是可截断的元数据。
- 日期、数字和复数通过国际化库格式化。
- 中英文混排时，产品名、代码和路径保持原文；不要手工插入大量空格控制版式。
