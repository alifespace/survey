# 实施与验收

## 推荐实施顺序

### 阶段 1：基础层

1. 建立颜色、字体、间距、圆角和阴影变量。
2. 配置深色、浅色和跟随系统三种主题模式。
3. 完成页面容器、Section、Stack、Grid 等布局原语。
4. 加载字体时使用 `font-display: swap`，并提供系统字体回退。

交付标准：一个令牌预览页能同时展示两个主题，正文和操作对比度通过 WCAG AA。

### 阶段 2：原子组件

实现按钮、链接、输入框、Badge、Tabs、Tooltip、Dialog 和图标按钮。为每个组件补齐所有交互状态。

交付标准：键盘可完成所有操作，焦点清晰，禁用和加载状态不改变布局。

### 阶段 3：页面组件

实现导航、Hero、信任条、能力卡、产品演示窗口、代码块、案例卡、最终 CTA 和页脚。

交付标准：组件内容可配置，不把首页文案硬编码到基础组件中。

### 阶段 4：首页组装

按[首页架构](04-homepage-blueprint.md)组装内容。先完成静态信息层级，再增加交互和动效。

交付标准：关闭 JavaScript 时仍能读取核心价值、能力和行动入口。

### 阶段 5：验证与优化

覆盖 360px、768px、1024px、1440px 四个关键宽度，以及 200% 页面缩放。执行无障碍、性能和真实设备检查。

## 无障碍验收

- [ ] 所有功能都能仅用键盘完成。
- [ ] 焦点顺序与视觉顺序一致。
- [ ] 焦点环没有被 `overflow: hidden` 裁切。
- [ ] 文本和控件对比度达到 WCAG AA。
- [ ] 触控目标至少 `44 × 44px` 或具有等效点击间距。
- [ ] 表单字段具有永久标签、说明和错误关联。
- [ ] Dialog 打开后锁定焦点，关闭后恢复焦点。
- [ ] 颜色不是表达错误、成功或选中的唯一方式。
- [ ] 减少动态效果设置得到尊重。
- [ ] 200% 缩放时没有内容丢失或水平页面滚动。

## 性能预算

| 项目 | 目标 |
| --- | --- |
| LCP | 移动端良好网络下 `< 2.5s` |
| CLS | `< 0.1` |
| INP | `< 200ms` |
| 首屏关键图片 | 总计尽量 `< 350KB` |
| 字体 | 最多 2 个家族，首屏字重按需加载 |
| 首屏 JavaScript | 交互所需最小集合，产品 Demo 延迟加载 |

## 视觉验收

- [ ] 首屏只有一个视觉主角。
- [ ] 主要 CTA 在 3 秒内可被定位。
- [ ] 强调色没有被大面积滥用。
- [ ] 卡片主要通过边框和背景层级区分，而非重阴影。
- [ ] 标题、正文和元数据形成稳定的三层对比。
- [ ] 产品演示展示真实任务，不是装饰性假界面。
- [ ] 手机端组件重新排布，而非把桌面界面缩小。
- [ ] 深色和浅色主题都经过逐屏检查。
- [ ] 页面没有使用 Supabase 商标、原文案或容易造成从属误解的资产。

## 内容验收

- [ ] Hero 明确说明产品、用户和结果。
- [ ] 每个能力点都有产品证据或真实示例。
- [ ] 所有数字、Logo 和客户引语均有使用依据。
- [ ] 按钮使用明确动词。
- [ ] 错误状态说明恢复方法。
- [ ] 代码示例经过运行验证或明确标注为伪代码。

## 完成定义

只有同时通过响应式、键盘操作、对比度、减少动态效果、性能预算和内容核验，页面才算完成。视觉接近参考风格不是完成标准；清晰表达本项目的独特价值才是。
