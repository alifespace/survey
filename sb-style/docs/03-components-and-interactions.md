# 组件与交互

## 全局导航

### 结构

- 左侧：自有 Logo 与产品名
- 中间：3–5 个一级入口，可包含下拉菜单
- 右侧：文档、登录、主要 CTA
- 移动端：Logo、主要 CTA、菜单按钮；其余内容进入抽屉

### 行为

- 初始状态可与页面背景融合，滚动后增加半透明背景、模糊和底边框。
- 当前入口同时使用文字颜色和细小指示，不只依赖颜色。
- 下拉菜单按“用户任务”分组，不按内部组织架构分组。
- 打开菜单后，焦点进入菜单；`Esc` 关闭并把焦点还给触发按钮。

## 按钮

| 类型 | 用途 | 视觉 |
| --- | --- | --- |
| Primary | 每个区域唯一的主要动作 | 强调色填充，深色文字 |
| Secondary | 次要动作 | 表面色填充，细边框 |
| Ghost | 导航和低优先级操作 | 透明背景，悬停出现表面色 |
| Destructive | 删除或不可逆操作 | 危险色；必须有明确动词 |

规则：

- 标签使用动词，例如“创建项目”“查看演示”，避免模糊的“了解更多”。
- 加载时保留按钮宽度，显示进度但不抖动。
- 不要在同一视觉组里出现两个 Primary。
- 图标按钮必须有可访问名称和 Tooltip。

## Hero

Hero 由五个元素组成：

1. 可选的短标签或更新提示
2. 结果导向主标题
3. 一段 2–3 行说明
4. 一个主要 CTA 和一个次要 CTA
5. 产品实景或能力导航，作为进入下一节的视觉桥梁

避免：自动播放视频、超过两种强调色、四个以上按钮、没有产品证据的抽象口号。

## 能力卡片

- 使用不对称栅格比等宽六宫格更有节奏，例如 `2 + 1` 或 `3 + 2`。
- 每张卡片只回答一个问题：它是什么、解决什么、如何证明。
- 图标统一为 16px 或 20px 线性图标。
- 卡片可点击时，整张卡片都是链接，并提供清晰焦点态。
- Hover 只提升边框、背景或局部图形，不整体上浮造成页面晃动。

## 产品演示窗口

推荐结构：

```text
┌──────────────────────────────────────────┐
│  状态点  文件/视图名          操作区     │
├──────────┬───────────────────────────────┤
│  导航    │  真实产品内容                 │
│  或标签  │  代码 / 表格 / 图表 / 日志    │
└──────────┴───────────────────────────────┘
```

要求：

- 示例数据应有语义，不能使用无意义的 lorem ipsum。
- Tab 可通过键盘切换，活动态具有文字和结构提示。
- 代码行过长时横向滚动，不强制折行破坏格式。
- 小屏幕隐藏次要侧栏，保留核心任务；不要把桌面截图等比缩小。
- 可复制内容提供复制按钮及成功反馈。

## Logo 与社会证明

- Logo 墙使用单色、统一视觉高度，不制造品牌之间的权重差异。
- 客户数字必须可核验并标注范围或时间。
- 引语控制在 2–4 行，优先说明具体结果。
- 案例卡包含公司、结果、角色和进入完整案例的链接。

## 表单

- 标签永久可见，Placeholder 只提供格式示例。
- 错误信息紧邻字段，并说明修复方式。
- 输入框、帮助文本和错误信息通过 `aria-describedby` 关联。
- 成功提交后展示明确结果，而不是只让按钮变绿。

## 页脚

- 第一层：安全、可靠性或开源承诺
- 第二层：按任务组织的链接列
- 第三层：状态、法律条款、社交入口和版权
- 移动端链接列可折叠，但法律与状态入口始终可见。

## 状态矩阵

所有交互组件必须覆盖：

| 状态 | 必须表现 |
| --- | --- |
| Default | 基础样式和可理解的 affordance |
| Hover | 细微但明确的反馈 |
| Focus visible | 2px 焦点环，不能被裁切 |
| Active | 短暂按压或明度变化 |
| Disabled | 不可操作且原因可发现 |
| Loading | 防止重复提交，布局不抖动 |
| Error | 文字解释、恢复路径和必要的状态色 |
| Success | 确认结果，必要时提供下一步 |
